# VideoMind 视析 · 视频知识结构化平台

> **一批视频进去，一份可溯源、可检索、可导出的知识库出来——不用看完就知道里面讲了什么**

软件工程课程项目 · 4 人小组 · 交付截止 **2026-12-11**

---

## 一、它解决什么问题

知识/讲解类视频（技术教程、产品演示、系统介绍、课程、需求访谈）信息密度高，但**只能线性播放**：

| 使用者的困境 | 现状 | VideoMind 的做法 |
| --- | --- | --- |
| 手上有一堆视频，不知道该看哪个、看了讲了什么 | 只能逐条播放，时间成倍消耗 | **批量导入一批视频**，自动产出结论、要点、UML 草稿，**不用看完就掌握全貌** |
| 想找某个知识点，翻遍多个视频也找不到 | 只能靠记忆和播放器拖进度条 | **两层标签**（视频级 / 条目级）+ **跨视频检索**，直接定位到条目 |
| AI 生成的结论不敢信 | 无出处，无法核对 | **证据溯源**：每条结论都能定位到原始视频的时间点与片段，可回看原话 |
| 看完要整理成文档 | 手工复制粘贴 | **可插拔产物**（内容总结 / 知识点要点 / UML 草稿 / 代码块），一键导出**批次级 Markdown 文稿** |

**核心差异化：可信、可查、可带走。**
不是"把视频变成文字"，而是把一批视频变成**带证据链的结构化知识资产**。

## 二、它长什么样

```
批量导入本地视频（一个批次 = N 条）
   │
   ├─ ① 音频通道：ASR 转写 → 带时间轴字幕
   ├─ ② 画面通道：关键帧抽取 → OCR 识别代码 / 文字   ← 双通道策略模式
   │
   ▼
结构化解析（LLM）→ 章节 · 知识点条目 · 代码块
   │
   ├─ 产物可插拔（输出策略模式 OutputSchemaStrategy）
   │     ├─ 内容总结   ├─ 知识点要点   ├─ UML 草稿（用例/类/时序）   └─ 代码块
   ├─ 证据溯源：每条产物携带 时间戳 + 原话 + 来源片段 + 通道标注
   ├─ 标签建议：AI 自动打标（视频级 / 条目级），人工采纳或驳回
   │
   ▼
视频库 · 跨视频检索 · 溯源回看
   │
   └─ 导出：批次级 Markdown 文稿（UML + 总结 + 要点 + 溯源）
```

## 三、技术栈

| 层 | 选型 |
| --- | --- |
| 前端 | Vue3 + Vite + Element Plus + G6（图谱）+ Video.js |
| 后端 | FastAPI（Python） |
| 解析链路 | yueying 0.2.1（锁版本）+ DeepSeek API |
| 视觉识别 | PaddleOCR / 视觉模型（双通道策略模式） |
| 数据 | MySQL（业务实体）+ Redis（缓存） |
| 交付 | Docker Compose 一键启动 |

## 六、协作方式

- 分支模型：`feature/<name>-<topic>` → PR → **`develop`（集成测试分支）** → 每周版本冻结 → `main`；**禁止直推 main 与 develop**
- 提交信息：Conventional Commits（如 `feat(design): 类图新增 OutputSchemaStrategy 抽象`）
- **变更记录逐版本、逐人署名，禁止合注**（见 `CHANGELOG.md`）
- 图源文件（draw.io / PlantUML）入库，SVG 为导出物
- 完整规约见 [CONTRIBUTING.md](CONTRIBUTING.md)
