# VideoMind 视析 · 数据字典（图 6 配套）

> 口径来源：`backend/app/models.py`（SQLModel 实体）与 `backend/app/enums.py`（枚举）。
> 版本基线：`develop` @ `a7e0b1d`（2026-11-15，代码线 v0.16）。
> 表数：**11 张**（2026-11-16 已确认按 11 表口径）。`docs/产品定义.md` §六 已同步为 11 表：原写 9–10 表，差异来自 `tag` 与 `tag_binding` 是否合并；本字典与图 6 均按代码实际拆开计数。

## 1. 表清单

| # | 表名 | 中文名 | 作用 |
| --- | --- | --- | --- |
| 1 | `video_batch` | 视频批次 | 一次上传的 N 条视频，批次级状态与计数 |
| 2 | `video` | 视频 | 单条视频，含四阶段状态矩阵 |
| 3 | `segment` | 转写片段 | ASR 产出的带时间轴文本段 |
| 4 | `evidence` | 证据 | 时间戳 + 原话 + 片段帧 + 通道，支撑溯源 |
| 5 | `knowledge_item` | 知识条目 | 可插拔产物的统一载体，标签打在条目层 |
| 6 | `artifact` | 产物 | 条目下的结构化产物实例，与条目一对多 |
| 7 | `conflict_record` | 冲突记录 | F2 教学一致性校验的结果，一等数据对象 |
| 8 | `tag` | 标签 | 视频级 / 条目级共用的标签定义 |
| 9 | `tag_binding` | 标签绑定 | 标签到视频或条目的多态绑定 |
| 10 | `note` | 笔记 | 绑定条目与时间锚点的学习者笔记 |
| 11 | `revision` | 修订留痕 | 讲义人在回路的版本与状态机 |

## 2. 表间关系

| 关系 | 基数 | 外键 / 说明 |
| --- | --- | --- |
| `video_batch` → `video` | 1 : N | `video.batch_id` |
| `video` → `segment` | 1 : N | `segment.video_id` |
| `video` → `evidence` | 1 : N | `evidence.video_id` |
| `video` → `knowledge_item` | 1 : N | `knowledge_item.video_id` |
| `evidence` → `knowledge_item` | 0..1 : N | `knowledge_item.evidence_id` 可空 |
| `knowledge_item` → `artifact` | 1 : N | `artifact.item_id` |
| `knowledge_item` → `conflict_record` | 1 : N | `conflict_record.item_id` |
| `knowledge_item` → `note` | 0..1 : N | `note.item_id` 可空 |
| `knowledge_item` → `revision` | 1 : N | `revision.item_id` |
| `tag` → `tag_binding` | 1 : N | `tag_binding.tag_id` |
| `tag_binding` → `video` / `knowledge_item` | N : 0..1 | 多态：`target_type` + `target_id`，不设外键 |

> `tag_binding` 是多态绑定表：`target_type = video | item`，`target_id` 指向对应表的主键。因为目标表不固定，数据库层不建外键，完整性由应用层保证。

## 3. 字段字典

### 3.1 `video_batch` 视频批次

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK，自增 | 批次主键 |
| `name` | VARCHAR | NOT NULL | 批次名，默认由上传时间/文件名生成 |
| `created_at` | DATETIME | NOT NULL，默认 UTC 当前时间 | 创建时间 |
| `status` | ENUM(`BatchStatus`) | NOT NULL，默认 `pending` | 批次终态：pending / running / succeeded / partial / failed |
| `video_count` | INTEGER | NOT NULL，默认 0 | 批次内视频数，冗余计数便于列表展示 |

### 3.2 `video` 视频

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK，自增 | 视频主键 |
| `batch_id` | INTEGER | FK → `video_batch.id`，NOT NULL，INDEX | 所属批次 |
| `path` | VARCHAR | NOT NULL | 本地视频路径；API 视图不下发绝对路径 |
| `duration_ms` | INTEGER | NOT NULL，默认 0 | 时长（毫秒），解析后回填 |
| `status` | ENUM(`VideoStatus`) | NOT NULL，默认 `pending` | 单条视频终态 |
| `transcribe_status` | ENUM(`StageStatus`) | NOT NULL，默认 `pending` | 阶段 1：转写 |
| `visual_status` | ENUM(`StageStatus`) | NOT NULL，默认 `pending` | 阶段 2：关键帧 + OCR |
| `structure_status` | ENUM(`StageStatus`) | NOT NULL，默认 `pending` | 阶段 3：LLM 结构化 |
| `artifact_status` | ENUM(`StageStatus`) | NOT NULL，默认 `pending` | 阶段 4：产物落库与推送 |
| `error` | TEXT | NOT NULL，默认空串 | 最近一次失败原因（已脱敏/截断） |

> 四个 `*_status` 就是「四阶段 × N 视频」状态矩阵的列；单条重试只重置这四个字段，不重跑整批。

### 3.3 `segment` 转写片段

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK，自增 | 片段主键 |
| `video_id` | INTEGER | FK → `video.id`，NOT NULL，INDEX | 所属视频 |
| `start_ms` | INTEGER | NOT NULL | 片段开始（毫秒） |
| `end_ms` | INTEGER | NOT NULL | 片段结束（毫秒） |
| `text` | TEXT | NOT NULL | 转写文本 |

### 3.4 `evidence` 证据

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK，自增 | 证据主键 |
| `video_id` | INTEGER | FK → `video.id`，NOT NULL，INDEX | 所属视频 |
| `start_ms` | INTEGER | NOT NULL | 证据起始时间 |
| `end_ms` | INTEGER | NOT NULL | 证据结束时间 |
| `quote` | TEXT | NOT NULL | 原话/原文片段 |
| `frame_path` | VARCHAR | NOT NULL，默认空串 | 片段帧本地路径；无帧时为空 |
| `channel` | ENUM(`Channel`) | NOT NULL，默认 `asr` | 证据通道：asr / ocr / both |

> 证据是 F1 的核心：任一条目可通过 `knowledge_item.evidence_id` 回指到时间戳、原话与片段帧。

### 3.5 `knowledge_item` 知识条目

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK，自增 | 条目主键 |
| `video_id` | INTEGER | FK → `video.id`，NOT NULL，INDEX | 所属视频 |
| `type` | ENUM(`ArtifactType`) | NOT NULL | 条目类型：summary / uml_draft / key_points / code_blocks |
| `title` | VARCHAR | NOT NULL | 条目标题 |
| `content` | TEXT | NOT NULL | 条目正文；Markdown / Mermaid 等由产物 payload 承载 |
| `confidence` | ENUM(`Confidence`) | NOT NULL，默认 `inferred` | 明述 / 推断 / 低置信 |
| `anchor_ms` | INTEGER | NOT NULL，默认 0 | 条目在视频中的时间锚点 |
| `evidence_id` | INTEGER | FK → `evidence.id`，可空 | 关联证据；无证据时为空 |
| `ordinal` | INTEGER | NOT NULL，默认 0 | 同视频内排序 |

> `type` 表示条目属于哪类产物；`artifact.schema_type` 表示具体 payload 的结构类型。当前实现中两者一一对应，拆开是为了让「条目」与「产物实例」解耦。

### 3.6 `artifact` 产物

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK，自增 | 产物主键 |
| `item_id` | INTEGER | FK → `knowledge_item.id`，NOT NULL，INDEX | 所属知识条目 |
| `schema_type` | ENUM(`ArtifactType`) | NOT NULL | payload 的结构类型 |
| `payload` | JSON | NOT NULL，默认 `{}` | 产物结构；不同策略有不同字段 |

> 四个 `OutputSchemaStrategy` 实现分别生成 Summary / UML 草稿 / KeyPoints / CodeBlocks 的 payload；新增产物类型只加策略，不改主链路。

### 3.7 `conflict_record` 冲突记录

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK，自增 | 冲突主键 |
| `item_id` | INTEGER | FK → `knowledge_item.id`，NOT NULL，INDEX | 关联条目 |
| `source_a` | VARCHAR | NOT NULL，默认空串 | 冲突一方（时间点 / 原话摘要） |
| `source_b` | VARCHAR | NOT NULL，默认空串 | 冲突另一方 |
| `description` | TEXT | NOT NULL | 冲突说明 |

> F2 的一致性校验结果独立建模，不塞进条目的备注字段；前端在条目详情与证据抽屉中展示。

### 3.8 `tag` 标签

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK，自增 | 标签主键 |
| `name` | VARCHAR | NOT NULL，INDEX | 标签名；当前未设唯一约束 |
| `suggested_by_ai` | BOOLEAN | NOT NULL，默认 false | 是否 AI 建议标签，人工采纳/驳回后仍保留来源 |

### 3.9 `tag_binding` 标签绑定

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK，自增 | 绑定主键 |
| `tag_id` | INTEGER | FK → `tag.id`，NOT NULL，INDEX | 标签 |
| `target_type` | ENUM(`TagTarget`) | NOT NULL | 绑定目标：video / item |
| `target_id` | INTEGER | NOT NULL | 目标主键；多态，不设外键 |

> 当前未建 `(target_type, target_id)` 复合索引；按标签过滤条目时由应用层查询。若数据量增大，可在后续版本补索引。

### 3.10 `note` 笔记

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK，自增 | 笔记主键 |
| `user_id` | VARCHAR | NOT NULL，默认 `local` | 本地用户标识；范围外不做注册与权限 |
| `item_id` | INTEGER | FK → `knowledge_item.id`，可空 | 关联条目；允许独立笔记 |
| `content` | TEXT | NOT NULL，默认空串 | 笔记正文 |
| `anchor_ms` | INTEGER | NOT NULL，默认 0 | 时间锚点；默认继承条目锚点 |

### 3.11 `revision` 修订留痕

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK，自增 | 修订主键 |
| `item_id` | INTEGER | FK → `knowledge_item.id`，NOT NULL，INDEX | 关联条目 |
| `state` | ENUM(`RevisionState`) | NOT NULL，默认 `draft` | 讲义状态机 |
| `editor` | VARCHAR | NOT NULL，默认 `local` | 编辑者；无用户体系，固定 local |
| `edited_at` | DATETIME | NOT NULL，默认 UTC 当前时间 | 编辑时间 |
| `snapshot` | TEXT | NOT NULL，默认空串 | 修订快照（正文/差异序列化） |

## 4. 枚举字典

| 枚举 | 取值 | 用途 |
| --- | --- | --- |
| `BatchStatus` | `pending` / `running` / `succeeded` / `partial` / `failed` | 批次终态 |
| `VideoStatus` | `pending` / `running` / `succeeded` / `partial` / `failed` | 单条视频终态 |
| `StageStatus` | `pending` / `running` / `done` / `partial` / `failed` / `skipped` | 四阶段状态；`skipped` 用于无字幕降级 / OCR 关闭 |
| `Channel` | `asr` / `ocr` / `both` | 证据来源通道 |
| `Confidence` | `explicit` / `inferred` / `low` | 明述 / 推断 / 低置信 |
| `ArtifactType` | `summary` / `uml_draft` / `key_points` / `code_blocks` | 产物类型 |
| `TagTarget` | `video` / `item` | 两层标签的绑定目标 |
| `RevisionState` | `draft` / `pending_confirm` / `confirmed` / `revised` | 讲义状态机 |

### 4.1 讲义状态转移

| 当前状态 | 允许转移到 |
| --- | --- |
| `draft` 草稿 | `pending_confirm` 待确认 |
| `pending_confirm` 待确认 | `confirmed` 已确认；回退 `draft` |
| `confirmed` 已确认 | `revised` 已修订；回退 `draft` |
| `revised` 已修订 | `pending_confirm` 待确认 |

> 非法转移由应用层拒绝（422）；状态机图见图 7。

## 5. 索引与完整性

| 对象 | 索引 / 约束 | 说明 |
| --- | --- | --- |
| `video.batch_id` | INDEX | 批次下视频列表 |
| `segment.video_id` | INDEX | 按视频取转写 |
| `evidence.video_id` | INDEX | 按视频取证据 |
| `knowledge_item.video_id` | INDEX | 按视频取条目 / 工作台大纲 |
| `artifact.item_id` | INDEX | 按条目取产物 |
| `conflict_record.item_id` | INDEX | 按条目取冲突 |
| `tag.name` | INDEX | 标签检索；未设唯一 |
| `tag_binding.tag_id` | INDEX | 按标签取绑定 |
| `revision.item_id` | INDEX | 按条目取修订历史 |

## 6. 口径说明（合稿前请统一）

1. **11 表口径（已确认）**：差异来自 `tag` 与 `tag_binding` 是否合并。本字典、图 6、`docs/产品定义.md` §六、`docs/交付与排期.md`、`docs/分工与任务卡.md` 已统一按 11 表；若后续合稿要求改为 10 表，需五处同步回改。
2. **`Video.path` 与 API**：数据库保留本地路径，但 `/api/batches/{id}` 与 `/api/videos/{id}` 不下发绝对路径，只给 `file_name` + `media_url`；数据字典保留该字段仅用于说明存储。
3. **`TagBinding` 多态**：`target_type` 只允许 `video` / `item`；应用层校验 `target_id` 存在，数据库层不建外键。
4. **无用户表**：`note.user_id` 与 `revision.editor` 固定为 `local`；用户注册与权限在范围外，不因数据字典而新增 `user` 表。
5. **`Artifact.payload` 结构**：JSON 字段随 `schema_type` 变化，具体字段由 `backend/app/artifacts.py` 的 Pydantic payload 模型定义；本文不把某一类的 payload 字段写成所有产物的通用字段。
