## 一、视觉系统：刻度尺

**一句话：把每条视频画成一把尺子。**知识点是尺子上的刻度，讲错的地方是一段红色斜线。学习者不用看完视频，扫一眼尺子就知道哪里讲了什么、哪里讲错了、哪里最该复习。

| 规则 | 做法 | 为什么 |
| --- | --- | --- |
| 色彩 | 黑 `#0A0A0A`、白、灰阶，加一种红 `#E4002B` | 红色只表示「易错 / 讲错 / 当前位置」，一眼就能找到要注意的地方 |
| 大数字 | 每页最大的数字都是用户最想知道的量 | 视频库「12 条」、进度「3/5」、检索「04 条命中」、后台「14.8 GB」 |
| 刻度尺 | 反复出现在工作台、视频库、进度、检索、后台 | 「可溯源」是产品的差异化，让它成为主视觉而不是一个小图标 |
| 编号圆标 | 实心 = 明述，空心 = 推断，虚线 = 低置信；红色 = 易错 | 置信度三档靠笔画区分，不依赖颜色，色弱用户也分得清 |
| 版面 | 2px 黑线分区，12 栏网格；直角、无投影、无圆角卡片 | 避开模板化的卡片后台风格，信息层级靠字号和线条 |
| 字体 | 数字 Inter Tight，中文思源黑体，代码与时间码 JetBrains Mono | 数字要大要紧凑，时间码要等宽对齐 |
| 可访问性 | 正文对比度 ≥ 4.5:1，焦点有 3px 红色描边，按钮高 ≥ 34px | 答辩投屏远处也看得清 |

## 二、页面优先级

按学习者的使用路径分三级，画图精力按级分配：

- **一级 · 主线页**（每次都经过）：02 批量上传 → 03 批次进度 → 04 知识工作台 → 05 证据链 → 09 导出
- **二级 · 回访页**（解析完反复用）：01 视频库、08 标签与检索、07 笔记编辑
- **三级 · 辅助页**（低频或特定画像）：06 UML 草稿、11 设置、10 批次后台、12 异常态

答辩演示动线（§4.1 指定）：**04 点大纲 → 播放头跳转 → 切产物面板 → 点条目拉出 05 证据抽屉 → 点 UML 节点回证据时间点**。

## 三、逐页说明

每页按「用户任务 / 首屏主角 / 取舍与隐藏理由」三段写；「热区」是墨刀里要做的点击跳转；「比现网多」是原型画了、代码暂未实现的部分。

### 01 视频库首页 · `p01-library@2x.png`

- **现网对应**：`/` LibraryView
- **用户任务**：找到之前那批视频，看讲了什么、处理完没有。
- **首屏主角**：大数字「12 条视频，3 个批次」；每个批次一行，左边批次名和状态，右边一把批次刻度尺（色块长短 = 视频时长，黑完成 / 斜线解析中 / 红失败 / 灰排队）；尺子下面直接列每条视频的**一句话结论**。
- **取舍与隐藏理由**：
  - 不做卡片网格，改成一批一行：一句话结论需要横向空间，卡片会把它截断。
  - 标签筛选放在第一排（§4.1 关键点），状态筛选降为右侧下拉。
  - 删除收进「更多」，避免误点。
  - 每批只列前 3 条，其余显示「还有 N 条」，保证三个批次都在首屏。
- **热区**：批次名 → 03；视频行 → 04；「批量上传」→ 02；「导出」→ 09。
- **比现网多**：卡片上的一句话结论（每条视频已有 `one_line`，W5 可顺手做）；按标签筛选。

### 02 批量上传 · `p02-upload@2x.png`

- **现网对应**：`/upload` UploadView
- **用户任务**：把一堆本地视频丢进来，开始解析。
- **首屏主角**：大数字「05 条视频可以解析」和合计时长；拖拽区；素材清单（每条带时长条，重复和格式不支持的直接划掉标红）；右侧「开始解析 5 条」主按钮。
- **取舍与隐藏理由**：
  - 解析参数只显示一行摘要，细节放设置页：上传时用户关心的是「能不能解析」，不是引擎参数。
  - B 站链接 Tab 置灰，标「仅原型」（§4.1 要求占位，范围外不做）。
  - 批次名给默认值，不强迫用户先起名。
- **热区**：开始解析 → 03；修改参数 → 11。
- **比现网多**：B 站 Tab 占位。

### 03 批次进度 · `p03-progress@2x.png`

- **现网对应**：`/batches/:id` BatchProgressView
- **用户任务**：还要等多久，哪条出了问题。
- **首屏主角**：大数字「3/5」；整批刻度尺（每格 5 分钟）；失败条目**置顶**并带红色「重试本条」；四阶段 × N 状态矩阵（完成实心、进行中斜线、等待浅灰、失败红、降级跳过虚线框）。
- **取舍与隐藏理由**：
  - 部分成功用一条红线加一句话提示（§4.1 关键点），不弹窗。
  - 解析事件流默认折叠：它是排障信息，普通用户不需要看。
  - 「整批重跑」收进事件流里：它会覆盖已完成结果，不该和「重试本条」并列。
- **热区**：去工作台 / 打开工作台 → 04；导出已完成 → 09；重试本条（就地变为进行中）。
- **比现网多**：顶部总进度大数字和整批刻度尺（现网只能逐行看，W5 可顺手做）。

### 04 知识工作台 · `p04-workbench@2x.png` · 核心页、可点击

- **现网对应**：`/videos/:id` WorkbenchView
- **用户任务**：不看完视频就知道讲了什么，并跳到想看的地方。
- **首屏主角**：
  - 顶部可点击刻度尺：章节色块（当前章节变红）、6 个编号圆标、12:55–18:40 红色斜线「说法前后不一致」、红色播放头。
  - 右栏默认打开**总结**：一句话结论最大，下面 3 条要点带时间码，再下面红色「考前注意 · 2 处易错」。
  - 中间播放器和大号当前时间；左栏章节大纲。
- **取舍与隐藏理由**：
  - 右栏默认「总结」而不是「要点」：主画像是考前复习，先给结论。
  - 原话转写折叠为左栏第二个标签：信息量大但不常看。
  - 同批视频切换放右上角下拉，不占主区域。
  - 易错点用红色块单独拎出来，因为「不一致是学习者最大的坑」（产品定义 F2）。
- **热区**（墨刀里要连成一条线）：
  1. 点章节色块 / 大纲条目 → 播放头、画面、字幕一起跳转
  2. 切换 总结 / 要点 / UML / 代码块 面板
  3. 点编号圆标或要点标题 → 拉出 05 证据抽屉
  4. 点 UML 节点 → 跳到证据时间点并提示
  5. 记笔记 → 07
- **比现网多**：刻度尺式时间线（现网是三色刻度条）。

### 05 条目详情 · 证据链 · `p05-evidence@2x.png`

- **现网对应**：工作台内 EvidenceDrawer（无独立路由）
- **用户任务**：这条结论能不能信。
- **首屏主角**：右侧抽屉；大号编号圆标 + 结论标题；**红线划掉的 12:55 原说法**和 18:40 更正原话，各带可点时间码；原话引用；回放按钮；来源帧（红框标出识别区域）。
- **取舍与隐藏理由**：
  - 画成工作台的抽屉态而不是独立整页：用户核对完要立刻回到原来的位置（§4.1「证据链抽屉」）。
  - 冲突提示放在原话之前：有冲突时这是最重要的信息。
  - 「识别结果仅供参考」固定在底部，不抢视觉。
- **热区**：时间码 / 回放 → 关闭抽屉并跳转；从这条建笔记 → 07；关闭 → 04。

### 06 UML 草稿 · `p06-uml@2x.png`

- **现网对应**：工作台产物面板「UML」标签页
- **用户任务**：（需求岗画像）拿到一份能拿去评审的图草稿。
- **首屏主角**：「用例 / 类 / 时序 / 流程」四个大字做切换标签；当前图；右侧选中元素的证据（原话、大号时间码、回放按钮）。选中元素变红。
- **取舍与隐藏理由**：
  - 对学生是辅助页，但「UML → 证据回跳」是 §4.1 点名的演示动线，所以单独成页画全四种图。
  - Mermaid 源码收进「复制源码」按钮，不展示代码。
- **热区**：切换图种；点元素 → 右侧证据更新；在工作台回放 → 04。
- **比现网多**：用例、类、时序三种图（现网只出章节流程图）。

### 07 笔记编辑 · `p07-notes@2x.png`

- **现网对应**：`/notes/:id` NotesView
- **用户任务**：记下自己的理解，以后能跳回原片。
- **首屏主角**：顶部来源条目（红色编号 3、标题、原话和时间码，并提示讲师 12:55 说过相反的话）；「插入时间锚点」主按钮；Markdown 编辑与预览左右分栏，预览里时间锚点可点。
- **取舍与隐藏理由**：
  - 讲义正文、四态状态机（草稿 → 待确认 → 已确认 → 已修订）和版本记录放进第二个标签「讲义」：编辑和改状态是同一时刻的事，但不是每次记笔记都要碰。
  - 同一条目多条笔记用右上角下拉切换。
- **热区**：时间锚点 → 04 对应时间；讲义标签内的状态流转按钮。

### 08 标签与检索 · `p08-search@2x.png`

- **现网对应**：`/search` SearchView
- **用户任务**：考前把某个知识点从所有视频里捞出来。
- **首屏主角**：超大搜索词「解构」；已选标签；大数字「04 条命中」；结果列表（命中词标红、原话、所属视频、置信度圆标），每条右侧一把小尺子标出它在视频里的位置。
- **取舍与隐藏理由**：
  - 明确写「按标签和关键词过滤，不是语义检索」（产品定义诚实边界）。
  - AI 标签建议做成带红色数字的按钮，点开抽屉逐条采纳 / 驳回；标签管理同样放抽屉：都是低频操作，不占结果区。
- **热区**：结果行 → 04 对应条目；AI 标签建议、管理标签 → 侧抽屉。
- **比现网多**：标签管理；AI 标签建议队列（现网只在工作台）；结果位置小尺子。

### 09 导出 · `p09-export@2x.png`

- **现网对应**：`/batches/:id/export` ExportView
- **用户任务**：把这一批的成果带走。
- **首屏主角**：大数字「4 条视频进入文稿」；下载 / 复制两个按钮；红线提示「缺 1 条」并给出去重试入口；文稿预览（每条要点带时间码）。
- **取舍与隐藏理由**：
  - 缺失条目放在最显眼处：拿不完整的文稿去复习会漏看。
  - 版本记录区块按 §4.1 保留在右侧，只读，只列已确认和已修订版本，修改入口指向 07。
  - 结构化接口说明默认折叠，普通用户不需要。
- **热区**：去重试 → 03；去讲义修改 → 07。
- **说明**：本页画的是 04 号视频解析完成后的时刻，所以是「4 条」；03 进度页画的是更早的时刻。

### 10 批次与任务后台 · `p10-admin@2x.png`

- **现网对应**：无独立路由（功能分散在视频库和进度页）
- **用户任务**：清理旧批次，看占了多少空间。
- **首屏主角**：大数字「14.8 GB 占用在本机」；占用分布条（每格 1 GB，勾选的批次变红）；批次表格；「已选 1 个 · 可释放 5.2 GB」。
- **取舍与隐藏理由**：
  - 入口放在顶栏右侧「系统」组，和设置并列：低频操作，不进工作区。
  - 删除需要二次确认，且明确写「原视频文件不受影响」。
- **热区**：批次名 / 查看 → 03；重试失败条目 → 03；删除所选 → 就地确认。
- **比现网多**：整页（存储占用、批次表格）。

### 11 设置 · `p11-settings@2x.png`

- **现网对应**：`/settings` SettingsView
- **用户任务**：第一次用时配好大模型，之后基本不再来。
- **首屏主角**：1、2、3 三个大数字标出首次配置顺序：大模型（Key 与测试连接）→ 画面识别引擎 → 默认产物集。
- **取舍与隐藏理由**：
  - 编号是真实的配置顺序，不是装饰。
  - 「用讲师的话校正屏幕上的专有名词」（ASR 词表校正）必须露出，标「设计态」：它是 §4.1 关键点，也呼应策略模式评分点。
  - 应用更新、深色模式、关于收进「更多」。
- **热区**：测试连接（就地显示结果）；OCR 引擎单选；产物多选。
- **比现网多**：ASR 词表校正开关（后端有配置，界面没有）。

### 12 异常态 · `p12-errors@2x.png`

- **现网对应**：无独立页面，分布在进度页、工作台、导出页
- **用户任务**：出错时知道发生了什么、下一步怎么办。
- **首屏主角**：A / B / C 三格——单条失败、无字幕降级、**批次部分成功**；每格都按「发生了什么 / 保住了什么 / 下一步按钮」三行写。
- **取舍与隐藏理由**：
  - 统一成三行句式，是为了让每种异常都告诉用户「已经保住了什么」，降低焦虑。
  - 技术错误详情折叠在「技术详情」里。
  - 批次部分成功单独成格，因为 §4.1 特别指出它「多数组会漏」。
- **热区**：重试本条；仍然查看 → 04；换引擎 → 11；导出已完成 → 09；重试失败 → 03。
- **比现网多**：无字幕降级的专门画面。
