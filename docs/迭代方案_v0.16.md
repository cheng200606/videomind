## 二、迭代项明细

### P0-1 axe 可达性全量扫描（亮 / 暗 × 全部页面）+ 修复

- **目标**：把「五页人工走查」升级为工具化全量扫描，产出可复现的可达性基线。
- **改动**：`npm i -D axe-core`（仅 devDependency）；通过浏览器自动化向页面注入 axe 并跑 `axe.run`，覆盖 9 个视图 × 亮/暗两态；violations 逐条修复或给出接受理由（写入报告）。
- **验收**：serious/critical 级 violation 清零（或逐条说明接受原因）；修复不引入回归（vitest/build 绿）；扫描脚本与结果留档。

### P0-2 Mermaid 图表暗色适配（含真实 LLM 产物验证）

- **目标**：暗色模式下 UML 草稿与主题一致，且用真实 LLM 输出验证渲染健壮性。
- **改动**：`MermaidView.vue` 监听 `html.dark` 类变化（MutationObserver 或 useTheme 状态），按当前主题用对应 themeVariables 重新 initialize 并重渲染；暗色变量与 `:root:root.dark` 令牌同值。
- **验收**：dev 库批次 2 的真实 UML 草稿在亮/暗两态渲染正确（截图）；亮色回归不变；组件逻辑有 vitest 覆盖（主题切换触发重渲染）。

### P1 whisper 档位实测（tiny vs base）

- **目标**：给「默认 tiny」这个用户可见决策提供实测依据（答辩素材）。
- **改动**：不改产品代码；用 v0.15 的合成讲座在同一环境分别以 tiny / base 转写，记录耗时与文本质量差异（繁简混排、同音错字率的人工抽查）。
- **验收**：报告含两档位的耗时表与质量结论；若 base 明显更优且耗时可接受，给出默认档位调整建议（改默认需另评估首次下载体积 75MB→~150MB 的取舍，本轮只给数据）。

## 五、关键决策与验证

1. **扫描通道选型**：node_repl 的 evaluate 有 3 秒上限且 axe.run 超时，改为「axe.min.js 拷入 /media 同源注入 → 起跑存 window → 轮询取结果」；每页独立 `open --browser msedge` 重启 daemon（循环里漏掉 msedge 参数是本轮排查最久的坑）。
2. **region 的修法是命名地标**：aside/main 本身是合法 landmark 但未命名时 axe 仍判 violation；实验确认加 `aria-label` 后 8 节点清零，落为模板属性。
3. **heading-order 的修复选在标题层级而非降级 axe 规则**：PageHeader h2→h1 让每页有唯一一级标题（语义上也更正确），section 标题 h3→h2 与之衔接；样式全部走类名选择器，标签替换零视觉影响（构建+截图确认）。
4. **whisper 档位对比走引擎直调而非 API 批次**：不污染 dev 库、绕过缓存；对比结论是数据而非拍脑袋，答辩可直接引用。
5. 诚实边界：axe 覆盖的是 axe-core 规则集（对比度/ARIA/地标/命名），键盘焦点顺序与读屏语义仍属人工测试范畴；whisper 对比基于合成音源，真实人声待素材。
