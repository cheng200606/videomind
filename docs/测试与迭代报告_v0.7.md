## 2. 测试方法与诚实边界

### 2.1 环境与数据

- 真实 ASR：`yueying 0.2.1` + `faster-whisper 1.2.1` + `av 18.1.0`（CPU，`tiny` 模型用于本轮速度；真实模型质量不代表生产环境）。
- 真实 OCR：`rapidocr 3.10.0` + `onnxruntime 1.31.1`（CPU）。
- 真实 LLM：DeepSeek `deepseek-flash`（通过设置页保存，测试连接 1092ms）；另用本地 OpenAI 兼容 mock LLM 做确定性 UI/全链路验证。
- 测试视频：用户提供的 `UML-6时序图.mp4`（27:56，1620×1080，H.264/AAC）；2 分钟片段由 ffmpeg 流复制得到；完整视频与片段均不入库。
- 隔离运行：`VMIND_DATA_DIR=output/e2e-v0.7/data`，端口 8000；前端 5173；没有污染 `backend/data/`。

### 2.2 诚实边界

- 真实 ASR 只评估这一条 UML 讲解视频；`tiny` 模型中文识别存在明显错字（如“状态图”识别为“状态筒”），不作为识别质量结论。
- 真实 OCR 只评估该视频的 8 张关键帧；不支持多语种/复杂版式的质量结论。
- 真实 DeepSeek 只验证连接与结构化可运行；输出质量取决于模型与提示词，不外推到其他视频。
- 未验证：多用户并发、SSE 队列持久化、真实移动设备、生产级长视频分片、MySQL/Redis/Docker 运行路径。
- 测试证据：`output/e2e-v0.7/`（截图、导出稿、结构化快照、响应式报告）本地留档，已被 `.gitignore` 覆盖，不入库。

### 3.3 失败与恢复

- 完整视频第一次失败：`yueying` 子进程在 faster-whisper STFT 阶段申请 440MiB 数组失败；批次/视频/阶段全部落 FAILED，可重试、可删除，没有永久 RUNNING。
- 重启后端并重跑同一批次：四阶段全部成功；说明是临时内存压力/进程状态问题，不是视频内容不兼容。
- 录制的错误文本原先截取 traceback 前 500 字；已改为优先展示最后一行异常，UI 可读性提升。
- 单条重试、整批重跑、批次状态重算均在真实失败场景中走通。

| 性能与稳定 | 4 | 2 分钟片段全链路秒级；完整 27:56 重跑约 107 秒；长视频第一次内存分配失败是明确边界；SSE 仍为单进程内存总线 |

**功能层主要不足（已修/已记录）**

1. 阶段④异常原先会穿出后台任务，批次永久 RUNNING 且无法删除（已修）。
2. 单条重试成功后原批次状态不重算（已修）。
3. 整批重跑 POST 后前端立即订阅，可能先收到旧终态并断流（已修：后端同步置 RUNNING + 前端重订阅）。
4. 空产物集可保存，导致批次成功但 0 条目（已修：422 + 前端至少保留一项）。
5. 非终态导出/结构化快照没有保护，且快照泄露本机绝对路径（已修：409 + file_name/media_url）。
6. 上传同名判断大小写敏感、写盘异常留 PENDING 孤儿、无大小上限（已修：casefold/清理/2GB）。
7. 笔记页只编辑 notes[0]，工作台每次新建导致重复笔记（已修：最新/指定 note + 不预创建）。
8. 进度矩阵只在批次终态刷新，运行中不更新（已修：SSE 事件驱动阶段矩阵 + 终态快照）。
9. 长视频单文件 ASR 存在临时内存分配失败；重试可恢复，但尚未实现自动分片/流式（已记录）。
10. LLM 输入截断 12000 字符，28 分钟视频的结构化覆盖不完整（已记录）。

## 9. 未做与后续建议

1. 长视频 ASR 分片/流式处理：当前 27:56 单文件在内存压力下可能失败，重试可恢复；建议按 5–10 分钟切分或换更大内存/GPU，仍按单批次多视频处理。
