## 一、我们要做什么

**VideoMind 视析** —— 面向**知识/讲解类视频**的批量结构化平台。

> 一批视频进去，一份可溯源、可检索、可导出的知识库出来——不用看完就知道里面讲了什么。

覆盖的视频类型：技术教程、产品演示、系统介绍、课程录播、需求访谈。共同特征是**信息密度高但只能线性播放**。

我们做的不是"把视频变成文字"，而是把一批视频变成**带证据链的结构化知识资产**。三个词概括差异化：**可信、可查、可带走**。

---

## 二、解决谁的什么问题

| 使用者的困境 | 现状 | 我们的做法 |
| --- | --- | --- |
| 手上几十条视频，不知道该看哪个、看了什么 | 逐条播放，时间成倍消耗 | **批量导入**，自动产出结论 / 要点 / UML 草稿 |
| 想找某个知识点，翻遍多个视频找不到 | 靠记忆 + 拖进度条 | **两层标签** + **跨视频条目检索**，直接定位到条目 |
| AI 生成的结论不敢信 | 无出处，无法核对 | **证据溯源**：每条结论定位到时间点 + 原话 + 片段帧 |
| 看完还得手工整理成文档 | 复制粘贴 | 一键导出**批次级 Markdown 文稿** |

### 目标用户画像

1. **计算机专业学生**（主画像）：一学期 3 门网课 + B 站教程，需要在考前把散在各视频里的知识点捞出来复习
2. **需求/产品岗**：手里握着客户访谈录屏与产品演示，要把它变成可评审的需求条目和 UML 草稿
3. **企业内训 / 教研室**：一批内部录播课，需要批量沉淀成带出处的知识库

## 三、核心链路

```
批量导入本地视频（一个批次 = N 条）
   │
   ├─ ① 音频通道：ASR 转写 → 带时间轴字幕
   ├─ ② 画面通道：关键帧抽取 → OCR 识别代码 / 文字   ← 双通道策略模式
   │
   ▼
结构化解析（LLM）→ 章节 · 知识点条目 · 代码块
   │
   ├─ 产物可插拔（输出策略模式 OutputSchemaStrategy）
   │     ├─ 内容总结   ├─ 知识点要点   ├─ UML 草稿（用例/类/时序）   └─ 代码块
   ├─ 证据溯源：每条产物携带 时间戳 + 原话 + 来源片段 + 通道标注
   ├─ 置信度分级：明述 / 推断 / 低置信
   ├─ 标签建议：AI 自动打标（视频级 / 条目级），人工采纳或驳回
   │
   ▼
视频库 · 跨视频检索 · 溯源回看 · 讲义修订留痕
   │
   └─ 导出：批次级 Markdown 文稿（UML + 总结 + 要点 + 溯源）
```

## 四、功能清单

### 4.1 平台基础能力

| # | 能力 | 说明 |
| --- | --- | --- |
| B1 | 批量视频接入 | 多文件选择，一个批次 = N 条；格式校验 + 重复检测 |
| B2 | 批次进度与单条重试 | 四阶段 × N 视频状态矩阵；单条失败不重跑整批 |
| B3 | 双通道解析 | ASR 字幕 + 关键帧 OCR，输出带时间戳的转写与帧图 |
| B4 | 知识工作台 | 播放器 + 左大纲 + 右产物面板（总结/要点/UML 切换），点任一要点跳转时间戳 |
| B5 | 两层标签 | 视频级 / 条目级；手动 + AI 建议，人工采纳或驳回 |
| B6 | 跨视频检索 | 按标签 + 关键词过滤条目（**是标签过滤，不是语义检索**） |
| B7 | 笔记与时间锚点 | 任意条目一键建笔记，笔记绑定时间戳，支持双向跳转 |
| B8 | 批次级导出 | Markdown 文稿，含 UML / 总结 / 要点 / 溯源 |
| B9 | 设置 | OCR 引擎切换、ASR 词表校正开关、默认产物集 |
| B10 | 异常态 | 单条失败 / 无字幕降级 / 批次部分成功 |

### 4.2 创新功能包 F1–F5

设计来源：把「视频需求工程助手」的四个机制原生移植进教学场景——教程自带矛盾与版本演化，这些机制在教学场景里比在需求场景里更值钱。

| 功能 | 一句话 | 教学场景为何更值钱 |
| --- | --- | --- |
| **F1 证据链讲义** | 点任一结论即可回看原片、听到原话 | 杜绝"AI 幻觉"式不可信结论 |
| **F2 教学一致性校验** | 检出讲师前后矛盾 / 代码版本演化 | 讲师先讲用法 A 后改成 B——**不一致是学习者最大的坑** |
| **F3 易错点挖掘** | 从反复强调、纠错、演示错误写法中提炼复习清单 | 正面命中"想学却学不会" |
| **F4 不确定性分级** | 每条结论标 明述 / 推断 / 低置信 | OCR 天然有误，标不确定比假装确定更可信 |
| **F5 语音-视觉交叉校验** | 用讲师念出的变量名校正画面 OCR 专有名词 | 语音是天然 ground truth |

**人在回路**：讲义修订回写 + 版本记录（状态机：草稿 → 待确认 → 已确认 → 已修订）。

落地铁律（三条红线，不许突破）：

1. **原型仍 12 页**：F1–F4 全部在既有页面内改造，不新增第 13 页

## 五、架构落点：三个可插拔策略

| 策略接口 | 实现 | 作用 |
| --- | --- | --- |
| `OcrEngine` | 本地 OCR / 视觉模型 | 画面文字与代码识别（双通道） |
| `AsrVocabularyCrossChecker` | ASR 词表校正器 | 用语音校正专有名词（F5，课程版只做设计） |
| `OutputSchemaStrategy` | UML 草稿 / 内容总结 / 要点清单 / 代码块 | **同一份解析结果，按产物类型产出不同结构** |

## 六、数据模型（ER 图 9–10 表）

| 实体 | 关键属性 | 说明 |
| --- | --- | --- |
| `VideoBatch` | id, name, created_at, status, video_count | 一次上传的一批 |
| `Video` | id, batch_id, path, duration, status | 增 `batch_id` 归属批次 |
| `Segment` | id, video_id, start_ms, end_ms, text | 时间轴片段，归 `Video` |
| `KnowledgeItem` | id, video_id, type, title, content, confidence, evidence_id | **知识条目**——可插拔产物的统一载体，**标签打在这一层** |
| `Artifact` | id, item_id, schema_type, payload | 产物实例，与条目一对多 |
| `Evidence` | id, video_id, start_ms, end_ms, quote, frame_path, channel | 证据：时间戳 + 原话 + 片段帧 + 通道（ASR/OCR） |
| `ConflictRecord` | id, item_id, source_a, source_b, description | F2 冲突成为**一等数据对象** |
| `Tag` / `TagBinding` | id, name / tag_id, target_type(video\|item), target_id | 两层标签的统一绑定 |
| `Note` | id, user_id, item_id, content, anchor_ms | 可引用 `KnowledgeItem` |
| `Revision` | id, item_id, state, editor, edited_at | 讲义修订留痕与状态机 |

## 九、诚实边界（主动写进文档，不回避）

1. **通用化 ≠ 全品类**：定位是知识/讲解类视频，不承诺处理娱乐、新闻等无知识密度的内容
2. **UML 对非建模类视频会退化为要点清单**——这是输出策略的设计，不是缺陷
3. **批量是顺序处理**，不是并发调度
4. **跨视频检索是标签过滤**，不是语义检索（向量库留给毕设）
5. **AI 产出统一标注「识别结果仅供参考」**，不承诺准确率；F1–F4 的前提是"可溯源 + 可标注"，不是"AI 判断正确"
6. **文档中禁止出现**「首次」「唯一」「100% 准确」「完全自动」等无据表述

## 十一、差异化话术（需求章开头 + PPT 第 2 页用）

> 旧叙事：「把视频变成笔记」
> **新叙事：不只是提取，而是可信提取——每条结论都能溯源到原片原话，能自动发现教程自身的前后矛盾与版本演化，能指出学习者最该复习的坑。**

未来工作（毕设阶段承接，答辩留 30 秒）：把这条链路从"看见代码"推进到"恢复可执行代码"——利用教学视频中同一行代码在连续帧反复出现的**时间冗余**做多帧融合，配合 ASR 交叉校验。F5 是它的伏笔。
