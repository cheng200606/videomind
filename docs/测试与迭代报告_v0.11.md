# 测试与迭代报告 v0.11 — 双视角审视与健壮性迭代

日期：2026-11-07 · 执行：程夏（组长）· 基线：v0.10（信息架构重组 + 时间码设计系统之后）

## 一、审视结论

从「真实用户使用体验」与「专业开发者」双视角对 v0.10 做了一轮全面审视：用户视角走查了库页→上传→进度→工作台→笔记→导出→检索→设置全动线（含坏深链、空条件检索等边界）；开发者视角对后端 API 做了无界查询、上传边界、错误泄漏面、并发一致性、测试覆盖的结构化审计。

### 用户视角问题清单（U1–U7）

| # | 问题 | 影响 |
|---|---|---|
| U1 | 检索不填任何条件会返回全库条目（实测 42 条且随数据无限增长），无上限、无总数 | 「检索」退化成「浏览」，数据量大时卡顿且误导 |
| U2 | 坏深链（如 /videos/abc）显示中英混排错误（pydantic 英文 detail 直通 UI） | 用户看不懂、观感不专业 |
| U3 | LLM 结构化把转写截到前 12000 字符且无任何提示：约 20 分钟以后的讲座内容静默丢失 | 核心产出不完整且不可发现，与「可信、可溯源」定位冲突 |
| U4 | 库页批次卡只有总条数，部分成功的批次看不出「2 成功 1 失败」 | 多批次管理低效，必须逐个点进详情 |
| U5 | 工作台没有同批次视频切换 | 看完视频 1 想看视频 2 必须退回进度页，学习动线断裂 |
| U6 | 上传无文件数/总大小上限、无 Content-Length 预检 | 超大请求要传完才被拒；几十个文件可写满磁盘后 500 |
| U7 | 引擎异常文本（含临时目录等本机路径）可直通进度页错误栏与事件流 | 吓到用户、违背「不暴露落盘路径」的既有约定 |

### 开发者视角问题清单（D1–D5）

| # | 问题 | 影响 |
|---|---|---|
| D1 | 列表/检索类端点全部无 LIMIT 无总数；`_brief` 逐条 3 查询（N+1），search/tags/structured 均中招 | 数据量线性增长后核心接口从毫秒劣化到秒级、响应数 MB |
| D2 | 无全局异常处理器：未捕获异常回英文 "Internal Server Error"，FastAPI 自动 422 也是英文 | 前端只能显示不可读错误 |
| D3 | 上传只有单文件 2GB 校验，无文件数/总量/预检 | 同 U6 |
| D4 | 多批次可并发解析：SQLite 写锁冲突风险 + `_recompute_batch_status` 可能把还在解析的批次提前置终态 | 用户看到大量莫名失败 |
| D5 | 上述 1–4 均无测试覆盖（71 例中相关断言缺失） | 回归无保护 |

## 二、分优先级迭代方案与实施结果

### P0（正确性核心）

| 项 | 目标 | 范围 | 验收标准 | 结果 |
|---|---|---|---|---|
| P0-1 长文截断诚实化 | 截断发生时用户可见、产物可查 | llm.structure 增加 report 回传截断事实；pipeline 在事件流发「结构化·部分成功」事件并把提示写进摘要产物 payload（notice 字段）；工作台顶部横幅展示。不做分块结构化（范围外大改） | 截断时事件流可见提示、摘要 payload 带 notice、工作台显示横幅；短视频无提示；单测覆盖 | ✅ test_llm 新增 1 例；UI 待真实长视频回归 |
| P0-2 检索防全量 | 空条件不放行、结果有上限有总数 | 后端：空条件 422；命中数上限 200（`_SEARCH_LIMIT`）；返回 `{total, items}`；LIKE 通配符转义。前端：无条件禁用检索按钮 + 引导文案；显示「共 N 条（已显示前 200）」；类型契约同步 | 空条件 422；截断时 total=全量、items=200；UI 显示总数；前后端测试绿 | ✅ 后端 4 例新增/更新；vitest 同步 |
| P0-3 错误面收敛 | 任何错误用户看得懂、不泄路径 | main.py 增加 RequestValidationError → 中文 422 与全局 Exception → 中文 500（堆栈只进日志）；pipeline 新增 `sanitize_error`（剥 Windows/POSIX 绝对路径、控制字符），阶段失败/单条失败/SSE 异常消息统一过洗 | /api/videos/abc/items 返回中文 422（「应为整数」）；含路径异常入库前被清洗；error 字段不含 `C:\`、`/tmp/` | ✅ 后端 3 例新增；浏览器实测中文提示 |

### P1（高频体验）

| 项 | 目标 | 范围 | 验收标准 | 结果 |
|---|---|---|---|---|
| P1-1 工作台同批次切换 | 批内视频一键切换，不打断学习动线 | WorkbenchView 复用 getBatch 拉同批次视频，页头动作区加下拉（当前项标「当前 ·」），切换即路由跳转；无新增后端 | 批内 >1 视频时出现切换器；切换后数据正确重载；失败不阻塞主体 | ✅ 浏览器实测渲染与跳转 |
| P1-2 库页状态计数 | 卡片直接看出「2 成功 1 失败」 | GET /api/batches 一次 group by 聚合各批次视频状态分布 → `video_status_counts`；卡片新增分布行；types.ts 同步 | 列表接口返回计数；卡片渲染「成功 2 · 失败 1」；后端测试断言 | ✅ 后端 1 例新增 |
| P1-3 上传边界预检 | 超限早失败、磁盘不写爆 | 后端：单批文件数上限 20（422）；Content-Length 预检（>20GB+100MB 余量 → 413）；流式累计总量超 20GB 记 rejected。前端：提交前同规则校验 + 提示文案 | 21 个文件 422；超总量文件被拒但有效文件照常创建；413 在落盘前返回 | ✅ 后端 3 例新增；前端文案更新 |
| P1-4 解析互斥 | 同一时间只允许一个批次解析（顺序处理口径的显式化） | pipeline 新增 `ParseMutex`（进程级 claim/release）；create/reparse/retry 三个入口 claim，`_run_batch`/`_one` finally release；占用中 → 409「已有批次正在解析」 | 占用时新批次创建 409；后台任务结束释放；进程重启自然清空（孤儿恢复兜底） | ✅ 后端 1 例新增 |

### P2（打磨与性能）

| 项 | 目标 | 范围 | 结果 |
|---|---|---|---|
| P2-1 N+1 消减 | 批量预取 Evidence/Artifact/Video（chunked IN，400/批），`_brief` 支持注入；tags 一次分组；search/items/structured 全部改走批量路径 | ✅ 行为不变，83 例全绿 |
| P2-2 转写端点封顶 | transcript 上限 5000 段（防巨型响应），工作台命中上限时提示 | ✅ |
| P2-3 导出复制与检索引导 | 导出页新增「复制 Markdown」；检索页空条件引导文案 | ✅ |

### 明确不做（范围外，与选题冻结口径一致）

分块/分段 LLM 结构化、向量语义检索、结果分页跳页（当前 total+上限已够用）、暗色模式、上传断点续传、桌面关于页。
