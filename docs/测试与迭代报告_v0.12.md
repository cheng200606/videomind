# 测试与迭代报告 v0.12 — 完整度迭代：从「能跑的切片」到「可正常使用的正式发布」

日期：2026-11-07 · 执行：程夏（组长）· 基线：v0.11.0（已发布 GitHub Release）

## 一、审视结论：半成品感从哪来

以「真实用户拿到安装包，能否完整走通 上传 → 解析 → 检索 → 导出，且拿到的是整条视频的完整知识产物」为口径审视 v0.11.0，确认三处完整性缺口与两处发布质量问题：

| # | 缺口 | 影响 |
|---|---|---|
| G1 | 转写超 12000 字符被整体截断，仅前段参与结构化（v0.11 只做了「诚实提示」，内容仍缺失） | 讲座类视频普遍 30–90 分钟（约 2–6 万字符），核心场景的产物天然不完整——这是「半成品」感的最大来源 |
| G2 | 桌面安装包为控体积排除了 RapidOCR/onnxruntime 整套，且 Whisper 引擎只出转写不出关键帧 | 「ASR 转写 + 关键帧 OCR 双通道」是产品定义的核心差异化，在正式发布物里整体缺席；设置页 OCR 只剩「关闭」，用户无从得知原因 |
| G3 | Electron 打包带全部 55 个语言包（实际只用中英 2 个） | 安装包约 48MB 解包体积的无谓浪费，与 G2 的「控体积」动机自相矛盾 |
| G4 | 打包态默认 `OCR_ENGINE=none`，且设置页对「为什么只有关闭」无任何解释 | 即便未来内置了引擎，新装用户也默认用不上画面通道 |
| G5 | `asr.py` 注释断言「桌面版不打包 onnxruntime（避免和 ctranslate2 的 OpenMP 冲突）」 | 该论断从未实测；若真有冲突，G2 的解法需另寻，若有解法则排除理由不成立 |

## 二、分优先级迭代方案与实施结果

### P0（完整性核心）

| 项 | 目标 | 范围 | 验收标准 | 结果 |
|---|---|---|---|---|
| P0-1 LLM 分块结构化 | 长视频全部内容参与结构化，不再整体截断 | `llm.structure()` 按段边界切块（每块渲染后 ≤12000 字符），逐块调用后合并；OCR 文本按时间归属到块；合并后一次收尾调用补全局 one_line/tags（失败不致命）；个别块失败 → 阶段 PARTIAL、视频 PARTIAL、notice 写明缺失区间；新增 `StageStatus.PARTIAL` | 单测：分块数正确、跨块产物齐全、块失败容忍、全块失败抛错、收尾生效、OCR 归属正确；短视频行为不变 | ✅ 后端 6 例新增/改写全绿 |
| P0-2 独立关键帧抽样 | 不依赖 yueying 的画面通道帧来源 | 新增 `app/engines/frames.py`：av 解码按间隔采样（默认 30s）、16x16 灰度均值差去重（numpy 手写）；pipeline 在「OCR 启用且引擎未产帧」时自动补齐；独立缓存；失败只降级 | 单测：合成视频采样时间戳正确、同画面去重、坏文件返回空不抛异常；打包态实测抽帧+OCR 走通 | ✅ 后端 3 例新增全绿 |
| P0-3 桌面版内置画面通道 | 安装包开箱即用「双通道」 | spec 对 rapidocr/onnxruntime/cv2/PIL/shapely/pyclipper collect_all；`run_server.py` 默认 OCR=rapid（可导入时）；excludes 收窄（imagehash/scipy/paddle 仍排除） | 打包态：engines 列出 rapid；真实走完 whisper→VAD→抽帧→RapidOCR 四阶段；与 ctranslate2 同进程无 OpenMP 冲突 | ✅ 三轮烟雾验证通过（G5 论断实测证伪：ctranslate2 带 `libiomp5md.dll`、onnxruntime 无 OpenMP DLL，无同名冲突） |

### P1（发布质量）

| 项 | 目标 | 范围 | 结果 |
|---|---|---|---|
| P1-1 体积 A 级优化 | 安装包不因画面通道失控膨胀 | `electron-builder.yml`：`electronLanguages [zh-CN, en-US]`（55→2）+ `compression: maximum` | ✅ 已生效（最终安装包体积见 Release 资产） |
| P1-2 引擎可用性说明 | 「为什么只有这些选项」自解释 | 设置页 OCR 下新增 hint（列表只显示当前环境可用引擎、桌面版已内置 RapidOCR、关闭=只走音频通道） | ✅ 打包产物上实测渲染 |

### 体积账（实测）

- sidecar：245MB → **454MB**（+209MB，其中 cv2 113MB、onnxruntime 43MB、rapidocr 含模型 32MB、PIL/shapely 等 ~20MB）
- Electron 语言包：55 个 → 2 个（省约 48MB 解包体积）
- 安装包：193MB（v0.11.0）→ 见 Release（NSIS LZMA 最高压缩后增量显著小于解包增量）

### 明确不做（范围外，沿袭选题冻结口径）

向量语义检索、暗色模式、上传断点续传、PaddleOCR 入包（体积不成比例）、多块并行结构化（顺序调用保证时间序与速率友好）。

## 四、遗留与后续候选

- 真实长视频（≥1h 讲座）+ 真 Key 的端到端回归：分块耗时与 DeepSeek 速率需一次实跑观察（本次无可用 Key 预算，未实跑）
- 抽帧间隔 30s 对快切视频可能漏帧；去重阈值 6.0 偏保守（渐变动画会大量折叠）——待真实素材反馈再调
- 体积 B/C 级（裁剪 av 编码器 DLL、引擎运行时按需下载）仍待周会评审
- 检索相关度排序、真机/读屏人工测试、dark mode、桌面关于页（沿袭观察项）
